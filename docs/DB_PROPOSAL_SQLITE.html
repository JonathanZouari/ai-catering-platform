הערכים בדוגמה הם להמחשה בלבד, ולא נתון אמיתי של העסק. הערכים נשמרים כ-REAL כי יש בהם עשרוניים, וכל ערך יכול להיות NULL ("לא ידוע"). הטבלה מוגבלת לשורה אחת לכל מנה, ומנה בלי שורה לא מציגה ערכים תזונתיים בכלל.

בחירת חברת משלוח

שלבמה קורהמה נשמר ב-DB
1. הגדרההבעלים מוסיף את חברות המשלוח שהוא עובד איתן, וגם את השליח הפנימי אם ישcouriers(name, kind, contact_phone)
2. הזמנההלקוח בוחר "משלוח", עיר וכתובת. הוא לא בוחר חברת משלוחorders.courier_id = NULL
3. אישורהבעלים מאשר את ההזמנה ובוחר חברת משלוח מהרשימה הפעילהorders.courier_id = 2
4. הפסקת עבודה עם חברהמכבים אותה. ההזמנות הישנות ממשיכות להראות מי שלח אותןcouriers.is_active = 0

ה-DB לא יקבל חברת משלוח בהזמנת איסוף עצמי. דמי המשלוח ללקוח נשארים לפי delivery_zones, בלי קשר לחברה שנבחרה.

ניהול מלאי

ב-DB יש טבלת פריטים אחת עם עמודה kind, ויומן תנועות אחד. העמוד מציג אותן כשתי טבלאות, כי כך עובדים איתן ביום-יום. הסיבה לטבלה אחת: מזון ואריזות מתנהגים אותו דבר (כמות, סף הזמנה, קנייה, שימוש), ויומן אחד נותן היסטוריה אחת לכל המלאי. השורות כאן הן דוגמה בלבד.

איפה סטיתי מהמסמך הקיים

  1. איחדתי את events לתוך orders. היחס ביניהן הוא 1:1, וגם ה-UI מחזיק את האירוע בתוך ההזמנה. טבלה נפרדת רק מוסיפה JOIN.
  2. הורדתי את ai_conversations. יש שיחה אחת לכל הזמנה, אז ההודעות מקושרות ישירות ל-order_id.
  3. הורדתי את dish_dietary. גם היא ביחס 1:1, אז העמודות עברו ל-dishes.
  4. החלפתי את requested_at ב-time_slot_id, ושומרים העתק של שעות החלון בשליחה. ה-UI עובד עם חלונות זמן. ההעתק מבטיח ששינוי של חלון זמן לא ישנה הזמנות שכבר נשלחו.
  5. הוספתי access_token_hash. בלי החלטה על חשבונות משתמש (OPEN #1), כל מי שמחזיק את ה-ID של הזמנה יכול לפתוח אותה. נשמר רק hash של הטוקן.
  6. הלקוח נוצר רק בשליחת ההזמנה, ומזוהה לפי טלפון. זה מה שה-UI אוסף בפועל.

מה השארתי בחוץ, בכוונה

  • משתמשי admin: יש בעלים אחד, אז מספיקה סיסמה במשתני סביבה.
  • היסטוריית סטטוסים: decided_at ו-decision_note מספיקים כרגע.
  • טבלת כללי כמויות: הנוסחאות עוד לא הוחלטו (OPEN #3). השדות rec_per_guest ו-qty_step מחזיקים את הערכים הזמניים.
  • מתכונים (מנה ← חומרי גלם וכלי אריזה): בלי זה המלאי לא יורד אוטומטית כשהזמנה מאושרת. זו התוספת הבאה, אם תרצה הורדה אוטומטית.
  • מעקב משלוח מול חברת המשלוח (מספר משלוח, סטטוס): עד שתבחר חברה ונדע איזה API יש לה.
  • טריגרים ל-updated_at: SQLAlchemy מעדכן את השדה בצד האפליקציה.
