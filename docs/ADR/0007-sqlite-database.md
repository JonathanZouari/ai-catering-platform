# ADR 0007 — SQLite as the only database

## Status
Accepted. Replaces the Postgres part of ADR 0002. Supabase stays for Auth and Storage.

## Context
The project owner chose SQLite everywhere: the app, the tests and the deployed server. No live data existed, so nothing needed migrating and the Postgres migrations were replaced by one schema file.

## Decision
- One SQLite file, opened through SQLAlchemy with the standard-library driver. `DATABASE_URL` is `sqlite:///...`, and `build_engine` refuses anything else.
- On a server the file sits on a mounted volume, and exactly one app instance runs. `require_deployment_settings` refuses a relative path, which would be lost on deploy.
- Migrations run at container start through `scripts/migrate.py`, tracked in `schema_migrations`. The file can't be reached any other way, so this replaces applying SQL by hand.

What each Postgres feature became:

| Postgres | SQLite |
|---|---|
| `FOR UPDATE` row locks | Every non-GET transaction starts with `BEGIN IMMEDIATE` and holds the one write lock until it commits. Check-then-write can't be overtaken. |
| Concurrent reads | WAL mode. GET and HEAD requests read a snapshot and take no write lock. |
| `numeric(10,2)` | Whole hundredths in an integer (`Hundredths`), which also refuses values past ten digits. |
| `timestamptz` | UTC text (`UtcDateTime`), which comes back marked as UTC. |
| Enum types and regex checks | `CHECK` constraints, with `GLOB` for slugs and colors. |
| Column types | `STRICT` tables. |
| `uuid`, `gen_random_uuid()` | 32 hex characters, generated by `uuid4` or `randomblob`. |
| `jsonb` | JSON text with `json_valid` checks. |
| Foreign keys | The same composite keys. SQLite needs `pragma foreign_keys = on` on each connection. |
| RLS | Removed. It guarded the Supabase Data API, and nothing exposes the file that way. |
| FK to `auth.users` | Removed, as it's a different system. |

## Consequences
+ No database server, no connection string secret, and tests need no setup.
− **One writer at a time.** Writes queue for up to 30 seconds. So nothing slow may run inside a write transaction, including AI calls and emails.
− **One server.** The app can't scale past one instance, and a deploy has a short outage because the volume can't attach to two.
− **Backups are ours.** There's no provider point-in-time recovery, and the volume is a single point of failure until copies are kept elsewhere.
− **Not encrypted by the app.** Customer details sit in a plain file, protected only by the host's disk encryption and access controls.
− Deleting a login in Supabase leaves its `caterer_users` row, so remove both. If the row stays, a token already issued keeps working until it expires, though no new token can be issued.
− The fifth tenant defense is gone with RLS, while the code and composite foreign keys remain.
